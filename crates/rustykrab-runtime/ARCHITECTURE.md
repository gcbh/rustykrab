## Why it exists

This was `rustykrab-gateway::orchestrate`. Nothing in it is HTTP — it builds
the system prompt, derives the session's capability set, creates the
`AgentRunner`, installs the memory write-back callback and drives the loop —
but living in the Axum crate meant the CLI's Telegram and Slack loops
depended on a web server to do non-HTTP work, and anything embedding the
agent inherited tower, APNs, rate limiting and origin policy with it.

The split followed a seam that was already there, measured before anything
moved: `orchestrate` used 16 `AppState` fields, the HTTP handlers used 5, and
only 3 overlapped. `AgentContext` took the agent half; `AppState` kept auth,
rate limiter, origin policy, credential-page policy and the channel handles
the webhook routes deliver to, and went from 26 fields to 10.

## Errors are not status codes

The layer previously returned `Result<_, StatusCode>` with every failure as
`INTERNAL_SERVER_ERROR`. A Telegram loop was receiving an HTTP status for a
problem that had nothing to do with HTTP, and the only caller that could act
on it was the one that never needed to. `RuntimeError` is a plain enum; the
gateway maps it at its own boundary in `run.rs`, which is where that decision
belongs.

## Observations

- **No tests.** The extraction was behaviour-preserving and the crate is
  covered indirectly through `gateway` and the e2e suite, so this is a gap
  rather than a risk today. It stops being acceptable the moment the turn
  sequence moves here.
- **It does not yet contain the turn sequence.** Load conversation → snapshot
  persisted ids → append → run with heartbeat → `save_turn` → extract reply
  is still written out at six call sites across `cli` and `gateway`. That
  belongs here, and moving it is the single highest-value change left in the
  workspace — the `PendingLinks` drain bug came from exactly that
  duplication.
- **Zero `env::var` reads**, which together with `memory` makes it one of the
  two crates in the workspace that can be configured entirely by its caller.
- `RuntimeError` has one variant. That is honest for now — every failure
  genuinely is internal — but it will want splitting once the turn sequence
  arrives and callers need to distinguish "conversation gone" from "model
  unavailable".
