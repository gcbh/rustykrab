## Two memory tiers, written on different paths

`orchestrate`'s write-back hook fires on every message the *runner* produces
and writes it to working memory, which decays. `distill` handles the other
half: inbound channel messages never pass through the runner's
`push_message`, so they reached neither the hook nor memory at all — a gap
that left nothing the user typed in the store while the runner's own
synthesized prompts were there repeatedly.

`ingest_inbound` closes that and is also where the durable tiers are
written. It persists the raw turn to working memory unconditionally, then
asks a classifier whether the message carries anything still true next week.
Failure is closed — an unparseable or failed classification writes nothing
durable — which is only safe because the raw turn has already landed on the
same call.

Each fact the classifier returns is tagged, and the tag picks the stage:

| kind | stage | why |
|---|---|---|
| identity, contact | `Semantic` | The only stage the sweep never demotes; its demotion loop iterates episodic alone. |
| preference, instruction | `Episodic` | Retrievable at once, promotes on three accesses after seven days, decays if never used. |

The split is about whether *not being used* is evidence of irrelevance. For
a preference it roughly is. For a phone number it is the opposite — needed
rarely and urgently — and `Episodic` decays to `Archival` after 30+ idle
days, which `LifecycleStage::is_retrievable` excludes. An unrecognised tag
falls to `Episodic`, so a model typo can never inflate the permanent tier.

The classifier is `AgentContext::distiller`, a separate handle on the same
model with thinking off; `provider` cannot serve both because `think` is
provider-level config in the Ollama client, not a per-call flag. It is also
the seam for moving distillation to a larger model on another node.

## Outcome contracts are derived here, not passed in

`prepare_agent` derives a skill's `OutcomeContract` from whichever skill the turn
already resolved (`contract_for_active_skill`), rather than requiring each caller
to supply one on `RunOptions`.

That is a correctness point, not a tidiness one. When it was a caller's
responsibility, exactly one caller — the cron path — filled it in, so the same
skill produced verifiable evidence on a schedule and proxy evidence in
conversation, and a skill's standing depended on which door the turn came
through. An explicit `RunOptions::outcome_contract` still wins, for a caller that
knows something the registry does not.

The runner is also handed the deployment's `ProbeRegistry` here, so it can sample
the declared effects either side of the run. Both are attached only when outcome
capture is enabled; with it off, no contract is built and no probe is sampled.

## Why it exists

This was `rustykrab-gateway::orchestrate`. Nothing in it is HTTP — it builds
the system prompt, derives the session's capability set, creates the
`AgentRunner`, installs the memory write-back callback and drives the loop —
but living in the Axum crate meant the CLI's Telegram and Slack loops
depended on a web server to do non-HTTP work, and anything embedding the
agent inherited tower, APNs, rate limiting and origin policy with it.

The split followed a seam that was already there, measured before anything
moved: `orchestrate` used 16 `AppState` fields, the HTTP handlers used 5, and
only 3 overlapped. `AgentContext` took the agent half; `AppState` kept auth,
rate limiter, origin policy, credential-page policy and the channel handles
the webhook routes deliver to, and went from 26 fields to 10.

## Errors are not status codes

The layer previously returned `Result<_, StatusCode>` with every failure as
`INTERNAL_SERVER_ERROR`. A Telegram loop was receiving an HTTP status for a
problem that had nothing to do with HTTP, and the only caller that could act
on it was the one that never needed to. `RuntimeError` is a plain enum; the
gateway maps it at its own boundary in `run.rs`, which is where that decision
belongs.

## Observations

- **Tests cover `distill` and contract derivation only.** 14 tests are
  classifier parsing and tier routing; 5 pin `contract_for_active_skill`.
  The extraction that created this crate remains
  covered only indirectly, through `gateway` and the e2e suite — a gap
  rather than a risk today, but one that stops being acceptable the moment
  the turn sequence moves here.
- **It does not yet contain the turn sequence.** Load conversation → snapshot
  persisted ids → append → run with heartbeat → `save_turn` → extract reply
  is still written out at six call sites across `cli` and `gateway`. That
  belongs here, and moving it is the single highest-value change left in the
  workspace — the `PendingLinks` drain bug came from exactly that
  duplication.
- **Zero `env::var` reads**, which together with `memory` makes it one of the
  two crates in the workspace that can be configured entirely by its caller.
- `RuntimeError` has one variant. That is honest for now — every failure
  genuinely is internal — but it will want splitting once the turn sequence
  arrives and callers need to distinguish "conversation gone" from "model
  unavailable".
