The control layer of `docs/plans/control-layer-and-worker-fleet.md`: a
deterministic controller, in code and never a model, that schedules a graph
of work items, verifies every worker result from evidence, climbs a
resolution ladder on every failure, and surfaces to the user only when the
ladder is spent.

## Responsibility

Own the lifecycle of work. The model proposes (files items, reports typed
results, asks typed questions); this crate transitions. Readiness, cascade,
parent roll-up, leases, the ladder and notification are computed here from
the store's rows, so a restart re-derives the same state and nothing depends
on a model remembering its plan.

The crate does not own persistence (`rustykrab-store`), the shared data
types (`rustykrab_core::work`), the model-facing tools (`rustykrab-tools`)
or any channel. It reads and writes the store and calls workers through
adapters that sit above it.

## Invariants

- **The model proposes, code transitions.** No path in this crate lets a
  model set a status. Cascade statuses (`blocked(upstream_*)`,
  `cancelled(cascade | superseded)`) are written only by the controller and
  always name their origin item.
- **A filing is atomic.** `work_plan`, `work_file`, the ladder's capability
  items, an accepted proposal and the delivery import all go through the
  same validator and are accepted whole or rejected whole with every failed
  check named.
- **Closed is final.** A retry is a new item; the failed attempt and its
  ladder stay in the record. The one deliberate exception, the delivery
  plan's rebase cascade, belongs to the delivery controller.
- **Sequential work stays in one worker.** The graph orders work, waits on
  the world and fans out independent branches; validation flags a split made
  only for sequence.
- **Unreadable rows parse to the conservative case** (`failed`, `blocks`),
  as `rustykrab_core::work` defines, so nothing runs early.

## Dependencies

`rustykrab-core` for the work vocabulary and the `Error` type;
`rustykrab-store` for rows, leases, events, evidence, the outbox and the
archive. Nothing here depends on a model provider, a channel or the gateway.
`rustykrab-agent` depends on this crate to implement `Worker`.
