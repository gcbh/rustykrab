## First-round findings

### Finding 1: the redirect killed the link the user already had (fixed)

`google_credentials::ask` does not re-file while its link is live, because
superseding a request kills its link and a superseded link opens the same "Link
expired" page a real expiry does. The tool had no such guard. After the redirect
the model's request shared the canonical name, so it superseded the ask:

- Probe (E4): the first link resolved before the tool ran and did not resolve
  after it.
- Real daemon (E3): the Gmail tool's canonical row was `superseded` in 3/3
  trials.
- Live store (E6): each of the six Gmail episodes since 2026-09-13 follows this
  sequence, and both rows carry links. So in production the user would get two
  links, the first one dead.

**Fix (3442d67):** when the canonical name is a known credential with a live
link, the tool returns the existing request as `already_requested` instead of
filing. This mirrors `ask`.

### Finding 2: a brand was matched as a service (fixed)

The bare `google` alias rewrote Maps, Gemini, Google Cloud and YouTube keys into
a Gmail address and app password (E4), and the bare `claude` alias rewrote a
claude.ai login onto `anthropic_api_key`. Answering either would have
overwritten a credential the application runs on.

**Fix (3442d67):** an alias is now a set of words that must all appear in one
string. "Google" matches only beside "mail" or "calendar", and "Claude" only
beside "API". "Notion Calendar" still reaches `notion_api_token`. That was left
as is, since a Notion Calendar web login carries a URL and takes the website
path instead.

## Infrastructure and observability weaknesses

- The e2e credential suite records only the *count* of pending rows. It scored
  the round-1 defect (a superseded live link) as `filed_request`, the same as
  the fix. Recording row names, statuses and whether a superseded row had a live
  link would make this failure visible without the kept-dir inspection used
  here.
- The e2e credential suite runs without a public URL, so it never mints links
  and cannot see link loss at all.
