# Current execution-path capability proof

Base: published #706 `14507d969907e26fec2ea82662c8dd79b03cedd0`.
Branch: `codex/native-proof-binding`. #702 startup retries remain independent.

Recovery previously validated the latest stored generation/receipt without
rebinding it to the current executor context. NativeWorker offered no probe
scope because a host observation could not attest the native CLI boundary.

The controller now shares post-activatable tool extraction with the actual
brief and binds kind, tools, MCP, writable resources, read-only marker and stable
repository/base. Scope includes worker, selected Local/Host/Native path and
actual policy/ceiling digests. Temporary directories live only in ProbeContext;
run id, deadline, time and set order/duplicates do not change input identity.

Gate2 reconstructs current binding, including existing registry/adapter access
identity. A legacy or changed generation uses the existing bounded dispatcher
and free-slot checks for fresh observations. A new generation is persisted
before dispatch. Explicit unknown scopes are recorded once; an unchanged
Failed/Unobserved receipt never creates a probe each tick. Independent owner
holds and cumulative budgets remain unchanged. A terminal refusal allocates bounded diagnosis in the existing work graph,
without adding an independent incident ledger or promotion pipeline.

NativeWorker shares its actual host/native predicate with scope selection.
Host probes relay through IntegrationWorker and LocalWorker, revalidating each
boundary and re-attesting only a matching child observation. Native selection
stays Unobserved and never launches a CLI/model or substitutes host exec. Both
halves' configured policies bind the outer identity. Shell-deny filtering,
read-only ceilings, exact resource grants and serial-wait deadlines remain.

Verification uses real SQLite controller fixtures with scripted probe outcomes,
and separately the real Local producer and real NativeWorker host wrappers.
The focused preflight exercised actual Node execution, real resource calls,
path/policy changes, read-only/shell-denied/missing-directory refusals, serial
contention, restart reconstruction, legacy generations, unknown executors and
post-activatable requirements. Source and logs are retained in the task's
`antifragile-collaboration/native-binding-*` artifacts. Required full workspace,
strict lint and documentation checks are recorded in
`native-binding-verification.json`; this note alone is not a passing receipt.
The negative-control runner retains original failure evidence and restores the
source byte-for-byte before required checks.

Fixed version/resource availability is not arbitrary compilation, native CLI
operation proof, model diagnostic quality or owner-goal completion. No live
merge/deployment, Tailscale change or compaction-policy rollout is included.
Updated architecture: control, agent and CLI crate write-ups; no database or
crate dependency added.

Terminal gate2 refusals now append one controller Warning per durable generation
on the original item's event/investigation trail, with executor, selected path
and bounded reason. Unchanged rechecks do not duplicate warnings, probes or
owner questions. A Native-selected subscription has no registered producer,
so every registered need is Unobserved there. The existing sweep Batch allocates/reuses an owned internal investigation,
consuming an existing Improve rung and recording a once-per-generation action
marker. It keeps the original parked; no RESOLUTION_WAIT marker or original-run
spend/grant is invented. Pending internal work cannot revive the original.
Only this waiter's recorded diagnosis ids, once Done and git/replay verified,
refresh repair identity and trigger one new bounded probe at unchanged policy.
Unrelated or unverified landings do not. Actual Proof is still required, so a
landed but ineffective/undeployed repair cannot authorize revival.

Exhausted diagnosis budget or rejected allocation records a typed once-per-
generation failure and an owner notice through Batch::notify/Cause::Asked. This
creates no question record: answering a NeedsTool question can currently requeue
it, so that fallback would bypass Proof. The existing owner outbox gives the
failure visibility while preserving its hold. No new scheduler or authority.

The generation binding also includes the controller's configured daemon build
label (version/commit/dirty identity), excluding build time and invocation data.
A different deployed build triggers fresh observation even after the landed
repair was already probed under an older build. An unchanged or unknown build
label is not a new binary measurement; fixed availability proof and live
original-goal effectiveness remain distinct.

The once-per-generation action also indexes the real probe refusal in existing
error evidence, verified_by=capability_revival. failure_history can therefore
resolve its fingerprint and supply the investigation bundle instead of sending
an investigator blind. It creates no attempt_failure, original-run record,
usage charge or budget grant. Controller tests verify that lookup explicitly.
