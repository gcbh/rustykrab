## Infrastructure and observability weaknesses

- **CI:** `CI Pass` depends on `[check, test, fmt, audit, e2e]` but not on the Architecture Docs job (`.github/workflows/ci.yml`). A PR with stale docs therefore shows the aggregate green, which is how this PR's red check could be missed.
- **Build hygiene:** a shared `CARGO_TARGET_DIR` across worktrees links stale workspace crates into new binaries. A version stamp does not prove what code was compiled.
- **Logging:** tool log lines carry no trace id, so batch/trace correlation cannot be seen at runtime.
- **No e2e scenario covers a batch.** `rustykrab-e2e`'s scripted provider can emit multiple `toolCalls` in one step, but no scenario does. A batch containing `tools_list` or `credential_request` would have caught this in CI.

## Monitoring delta

Proposed, not added: alert on any `credential_requests` row with `link_token_hash` set and `conversation_id` NULL. That combination means a link was minted and can never be delivered, which is exactly the M4's lost Gmail request (22b7d0cc).
