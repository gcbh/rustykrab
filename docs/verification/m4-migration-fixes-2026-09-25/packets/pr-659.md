## Infrastructure and observability weaknesses

- The allowlist is only protected by a comment. Any new setting the daemon reads silently misses deployed machines until someone adds it here. A test that checks the loop against every `std::env::var("RUSTYKRAB_…")` the daemon reads would catch that; this PR doesn't add one.

## Monitoring delta

None added. Worth adding to the monitor: on each daemon start, log the effective `max_context_tokens` and `OLLAMA_TIMEOUT_SECS`, and alert when they differ from the operator's intended values. The loss on 2026-09-10 went unnoticed for two weeks.
